# com_biotime 1.3.8

Update from **System → Update → Extensions**, or install the attached package. No database changes.

This release follows a second full audit of the extension. Details are in `docs/AUDIT.md`.

**Wrong figures fixed**
- When a month could not be read from ZKBioTime (outage, timeout), every working day showed as
  **Absent** with 0% attendance, on the cards, charts and manager reports. Such days now show no
  status; the error notice stays.
- Days **before an employee's hire date** no longer count as Absent.
- The month that just ended is refreshed normally for 7 more days, so late punches and leave
  approved afterwards appear without waiting a day.
- After changing the connection, the time zone or the duration unit, the stored copies are
  emptied, so nobody sees months read with the old settings.

**Faster when ZKBioTime is down**
- Pages no longer wait for the connection timeout once per month: one attempt per page.

**Security**
- Data is shown only while the mapped employee code still belongs to the mapped employee in
  ZKBioTime.
- A user waiting for approval can no longer block the administrator from mapping that employee
  to someone else.
- User Mappings: opening another user after a failed save no longer shows (and saves) the first
  user.

**Administrator**
- Database "Off" can be saved while a password is stored.
- Diagnostics says when it could not finish.
- User Mappings search ignores upper and lower case on PostgreSQL.

After the update, pages read each month from ZKBioTime once more (the stored copies are renewed).
